Agentic AI Registrar Office: the whole problem

One map of what the project asks for, what it implies, and how we propose to solve it with a multi-agent system and LLM-based RAG. Colors show where each node comes from.

Agents (5)

Proposal
  • Routerchecks the role, classifies the intent, dispatches, writes the final answer with citations
  • Data agentRecords + Analytics merged: transcript, schedule, roster, statistics (same tools, same read permission)
  • Policy agentRAG over the handbook, with citations; no database access
  • Advising agentmulti-step course plans from Policy + Data results
  • Registration agentthe only agent with write tools (register, drop, enter grade); never sees retrieved policy text, so injected text cannot trigger a write
  • Plain code, not agentsregistration validatoraccess controlSQL executionGPA / statistics
  • Split by capability or permission boundary, not by step.

Retrieval (the RAG part)

Proposal
  • Structuredparameterized tools, e.g. get_transcript(sid), grade_distribution(course, sem)
  • Text-to-SQLfallback for ad hoc admin questions; schema + example retrieval; SELECT only, validated, read-only views
  • Documentschunk by sectionBM25 + densererankcite sources
  • Rule: SQL/Python computes numbers; the LLM only explains them.

Synthetic data

Decided
  • Database5 slide tables + prerequisites, degree requirements, enrollment, advisors, capacity
  • Handbooksynthetic, modeled on the real NMSU catalog policies (catalogs.nmsu.edu): academic standing, degree requirements, registration, grading
  • Gold answerscomputed by the generator's code
  • Realismstudent abilitycourse difficultyfixed seed
  • Scale~500 students60 courses25 professors8 semesters~15k grade rows
  • Planted casesdismissal, and just above120 credits, 1 core missingrepeats, W / Ihigh-F coursemissing prerequisite
  • RAG checksNMSU text is public, so the LLM may already know it: change a few thresholds from the NMSU values, and run a closed-book baseline; grad vs. undergrad distractors
  • Limit: shows the pipeline is correct, not performance on real registrar data.

Evaluation

Proposal
  • Test set50 to 100 questions per role, each with a gold answer
  • MetricsSQL execution accuracyretrieval recall@kfaithfulnesscitation correctness
  • Securityaccess-violation rate must be 0; prompt-injection tests
  • Baselinesingle agent with the same tools, same test set; report accuracy, safety, latency
  • Prior checkanswers that use the original NMSU or common default values instead of our modified ones show RAG failure

Decisions

Decided
  • Write accessread + write: registration and grade entry, checked by the validator, confirmed by the user before commit
  • LLMlocal model (e.g. Qwen or Llama via Ollama; size set by available GPU)
  • Frameworkour choice: LangGraph
  • Deliverablesno fixed requirement given
  • Local model means: JSON-schema structured output for tool calls, few tools per agent, local embeddings.
Project 1

Agentic AI Registrar Office

Multi-agent system + LLM-based RAG

Answer each role's questions correctly, from the database and the rules, within that role's access.

Goal

Slides
  • Design a multi-agent AI system that functions like a registrar office
  • Job 1maintain the databases
  • Job 2give each type of user the information they need

Users and needs

Slides
  • StudentsScheduleRegistrationTranscript
  • ProfessorsScheduleCoursesStatistics
  • AdministratorsCourse-group stats: grade spread, many As / FsStudent-group stats: will graduate, near dismissal
  • AdvisorsAdvising courses
  • "..."open-ended; we may add roles or tasks

Data (sample schema)

Slides
  • Students(ID, Name)
  • Grades(Student, Course, Semester, Grade)
  • Schedule(Course, Semester, Professor)
  • Courses(Course, Title, #Credits)
  • Professors(ID, Name)
  • Missing (inferred): prerequisites, degree requirements, capacity and time slots, current enrollment, advisor-to-student mapping. Added as synthetic tables.

Policies (rules not in the tables)

Inferred
  • Academic standingprobation and dismissal thresholds
  • Degree requirementscredits, core courses, minimum GPA
  • Registration rulesprerequisites, credit cap, deadlines
  • Grading scalepoints per grade, repeats, W / I / P-F
  • Catalogcourse descriptions, degree plan
  • Source (decided): synthetic handbook based on NMSU policies, consistent with the synthetic database.

Core challenges

Inferred
  • Understandingnatural-language question to the correct data
  • Rules"will graduate" and "near dismissal" are defined in policies, not tables
  • Exactnessstatistics must be computed, not guessed
  • Access controleach role sees only its own data
  • Safe writesregistration and grade changes must be validated
  • Groundinganswers cite the rule or query they used

How the branches connect: one example

An administrator asks: "Which students are near dismissal?"

  1. Routerverifies the admin role, routes the question
  2. Policy agentretrieves the dismissal rule from the handbook (RAG)
  3. Data agentturns the rule into a tool call or a validated SQL query
  4. Synthetic databaseGrades + Courses give GPA per student per semester (computed in SQL)
  5. Routerreturns the list, the cited rule, and the query used; checked against the gold answer
