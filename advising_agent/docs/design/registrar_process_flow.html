Registrar process flow

The full path of one user message: intake and clarification by the Router, work by the specialist agents and deterministic code, and the final answer. Circles marked 3 lead to stage 3.

LLM agent (Router or specialist) Deterministic code or tool User interaction Data store 3Go to stage 3 (Answer)
Read path

Administrator

"Which students are near dismissal?"

  1. Session gives role = admin. Router: intent = student-group statistics.
  2. Missing field: student group. Data field, so lookup lists the departments. Several options, so the Router asks: "All students, or one department?"
  3. User: "Computer Science." All fields filled, dispatch.
  4. Policy agent retrieves the dismissal rule from the handbook, with citation.
  5. Data agent turns the rule into a read tool call, e.g. students_by_gpa(dept, lo, hi); access control and DB return the list.
  6. Router composes: list + cited rule + query used + assumption (current semester).
Write path

Student

"Register me for databases."

  1. Session gives role = student, ID. Router: intent = register.
  2. Missing data fields: course, section. search_course("databases") finds CS 482 and CS 582; CS 582 is graduate-only, so one course remains.
  3. list_sections(CS 482, Spring 2027) finds 2 open sections, so the Router asks which one.
  4. User picks sec 02. Registration agent calls the register tool.
  5. Validator checks prerequisites, time conflicts, credit cap, capacity. Valid, so the user sees the exact change and confirms.
  6. Commit through access control, write audit log, Router confirms the registration.

Rules the diagram encodes

  • Identity and role come only from the login session.
  • Missing data fields are looked up before asking; missing user fields are asked directly.
  • At most 2 clarification rounds, then answer with stated assumptions.
  • Lookup tools are read-only and use the same access control.
  • Only the Registration agent has write tools, and it never sees retrieved policy text.
  • Every write needs validator approval and user confirmation.
  • Numbers (GPA, statistics) are computed by SQL or code, never by the LLM.
  • Every answer states its source: cited rule, query used, assumptions.
